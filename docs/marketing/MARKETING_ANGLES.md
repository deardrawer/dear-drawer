## 2. 기능-편익 번역표

| 기능 | 기술적 설명 | 사용자가 얻는 것 | 한 줄 카피 후보 |
|---|---|---|---|
| AI 문구 생성 | 답변 기반 인사말/프로필/스토리 초안 생성·재생성 | 글쓰기 막막함 해소, 5분 만에 초안 | "무슨 말을 쓸지 몰라도, 초안은 AI가." |
| 10종 템플릿 | 컨셉·컬러·폰트·애니메이션이 다른 10개 렌더러 | 우리 커플다운 무드를 고를 자유 | "10가지 무드, 우리 얘기는 하나." |
| 인트로 프리셋 10종 | 오프닝 애니메이션 프리셋 + 문구/배경 커스터마이즈 | 첫 화면부터 다르게 | "열자마자, 다른 청첩장." |
| 혼주 개인화 링크 | 하객별 맞춤 인사·열람 추적·비번 관리자 | 부모님이 지인 한 분 한 분께 격식 있게 | "부모님 이름으로, 한 분씩 정중히." |
| RSVP + 세부옵션 | 참석/식사/셔틀/하객구분 응답 수집·대시보드 | 식수·차량·좌석을 숫자로 | "받은 마음을 표로." |
| 방명록·D-Day 팝업 | 축하 메시지 수집 + 카운트다운 팝업 | 하객 참여 + 설렘 리마인드 | "그날까지, 함께 세는 시간." |
| 무료 제작·발행 | 워터마크 포함 무료 발행(제거만 유료) | 부담 없이 만들어 보고 결정 | "만들어 보고, 마음에 들면." → 가격은 BRAND_FACTS.md 참조 |
| 카카오/QR/문자 공유 | 링크·카카오 피드·QR(1024px)·SMS | 온·오프라인 어디로든 전달 | "링크로도, QR로도." |

## 3. 차별점 후보 (업계 대비 3단계)

**① 흔함 (모바일 청첩장 공통 — 차별로 쓰기 약함)**
- 기본 섹션(인사말·예식정보·갤러리·오시는 길·계좌), RSVP, 방명록, BGM, 카카오 공유, D-Day.
  - 근거: PRODUCT_CATALOG §2 — 업계 표준 기능들.

**② 흔치 않음 (경쟁 우위로 쓸 만함)**
- **뚜렷한 컨셉 템플릿 10종** — 레코드/필름/매거진/피드/에세이 등 무드가 확연히 다름. (`templates.ts`)
- **AI 문구 생성** — 인사말·프로필·스토리 초안. (`ai_generated_texts`)
- **인트로 프리셋 10종** — 오프닝을 통째로 교체. (`introPresets.ts`)
- **RSVP 하객 세분화**(본인/부/모, 식사·셔틀) — 실제 운영 수치화.

**③ 드묾 (강한 후크, 단독 소구 가능)**
- **혼주(부모) 전용 템플릿 + 하객별 개인화 링크 + 열람 추적 + 4자리 비번 관리자** — 혼주 시장을 정면으로 겨냥. (`narrative-parents`, `guests`, `invitation_admins`)
- **에세이 "책 넘김" 인터랙션 / 레코드 회전 / 필름 시네마 오프닝** — 인터랙션 자체가 콘텐츠.
- **그날(geunnal) 모임 관리 + Web Push 리마인더** — 청첩장에 이벤트 관리가 붙는 구조(범위 한정, PWA 설치·푸시는 geunnal 영역만). [개발중/범위 한정]

## 4. 설명이 필요한 기능 (사용자가 이해하기 어려울 것)

| 기능 | 왜 어려운가 |
|---|---|
| **그날(geunnal)** | "청첩장"과 별개인 모임 관리 대시보드(`/g/[slug]`). 청첩장 기능으로 오인 쉬움 — 관계 설명 필요 |
| **혼주 개인화 링크** | "하객마다 다른 링크"라는 개념이 생소. 왜/어떻게 쓰는지 예시 필요 |
| **로그인 없이 시작** | 편집은 로그인 없이 되지만 저장·발행 시 카카오 로그인 필요 — 기대와 어긋날 수 있어 안내 필요 |
| **AI 문구 vs 직접 작성** | "AI가 다 써준다"로 과대 기대 위험 — 초안 보조임을 명확히 |
| **템플릿 컬러/폰트 커스터마이즈 범위** | 템플릿마다 색·폰트 시스템이 달라(예: 더심플 사용자색, 에세이 전용 팔레트) 자유도가 균일하지 않음 |
| **워터마크/과금** | 무료·유료 경계 — BRAND_FACTS.md 참조. 오해 없게 문구 정리 필요 |
